# 网文查重网站 - 项目策划案（草稿）

## 一、项目概述

| 项目名称 | （待定）                                    |
| ---- | ---------------------------------------------------------------- |
| 项目定位 | 面向网文作者、编辑的**句子级查重工具**，基于 RAG 技术实现逐句语义匹配，精确到每一句话对应哪本网文的哪一句，并给出相似度 |
| 目标用户 | 网文作者、平台编辑、版权相关从业者                                                |
| 开发周期 | **2个月（约8周）**                                                     |
| 部署环境 | 后期上线阿里云服务器（4核4G），前期本地开发测试                                        |

## 二、核心功能清单（MVP）

| 模块    | 功能                                                      | 优先级 |
| ----- | ------------------------------------------------------- | --- |
| 用户系统  | 注册 / 登录 / 权限管理                                          | P0  |
| 文档上传  | 支持常见格式（txt/docx/pdf等），无严格限制                             | P0  |
| 查重核心  | RAG 句子级语义匹配：上传文档 → 逐句向量化 → 比对个人数据库 → 返回匹配结果（相似句+来源+相似度） | P0  |
| 查重报告  | 展示总体相似度、高亮重复句子、标注来源作品及具体章节/句子                           | P0  |
| 历史记录  | 展示用户过往查重记录，支持查看详情                                       | P1  |
| 权限与配额 | 不同用户角色享有不同查重次数限制                                        | P1  |
| 比对源管理 | 后台管理网文数据库（入库、更新、删除）                                     | P1  |

## 五、分工明细（纵向功能分工）

### 总体思路

- **小光（负责人）**：查重核心算法 + 全部基建/部署/CI，并负责接口契约、Code Review、联调兜底。
- **小浩、小霍**：各认领一条完整的纵向切片（后端接口 + 前端页面自己全做），互不交叉、压力均衡，每人都能跑通一遍全栈。
- 查重核心由小光封装成接口，两人只管对接，不碰向量库。

### 三块职责

| 角色 | 纵向切片 | 负责内容 | 产出 |
| ---- | ---- | ---- | ---- |
| **小光** | 核心与基建 | 脚手架、docker-compose、句子切分、Embedding 选型、FAISS 索引 + 检索、异步队列、比对源批量入库、部署/监控/CI、Code Review | 查重核心 API + 可上线环境 |
| **小浩** | 用户与历史 | 用户表 + JWT 注册/登录/刷新接口、登录/注册页、首页布局、认证状态管理、历史记录 API + 页面 | 完整「注册→登录→看历史」链路 |
| **小霍** | 上传与报告 | 上传文档 API + 拖拽上传组件、查重报告数据接口 + 结果页（相似度/高亮/来源）、配额扣减逻辑、全局错误/加载状态 | 完整「上传→查重→看报告」链路 |

### 接口契约（小光先定，小浩、小霍照此对接）

| 接口 | 用途 | 负责 |
| ---- | ---- | ---- |
| `/api/auth/register` `/login` `/refresh` | 认证 | 小浩 |
| `/api/upload` | 上传文档，返回文档ID | 小霍 |
| `/api/check`（提交查重，返回任务ID）+ `/api/check/{task_id}`（轮询结果） | 查重核心 | 小光 |
| `/api/report/{report_id}` | 报告数据 | 小霍 |
| `/api/history` `/api/history/{id}` | 历史记录 | 小浩 |
| `/api/quota` | 配额查询/扣减 | 小霍 |

> 提醒：轮询查重结果需要「上传→报告」跨小浩/小霍的切片，**查询任务状态的接口由小光实现，小霍只管展示**，避免小霍被 Celery 异步细节卡住。
